# 可视化回复

## 通道选择（先定通道，再动笔）

xihe 桌面端聊天**原生渲染两类可视化**：` ```mermaid ` 代码块（内置 mermaid v11，离线，明暗主题自适应）和 ` ```html type="renderer" ` 代码块（沙箱 iframe 内联渲染，支持交互与脚本）。GFM 表格可渲染；本环境**离线气隙，无任何 CDN**。

| 通道 | 何时用 | 交付方式 |
|------|--------|----------|
| **A · mermaid**（默认首选） | 流程图、架构图、时序、状态、ER、类图、甘特、时间线、思维导图、饼图、XY 折线/柱状、桑基 | ` ```mermaid ` 代码块，聊天内就地渲染 |
| **B · GFM 表格** | 数据的精确值、多指标对比、图表的兜底 | Markdown 表格，与图表并列输出 |
| **C · html renderer**（交互/动态） | 交互探索、动态演示、教学动画、mermaid 表达不了的富图表 | ` ```html type="renderer" ` 代码块，聊天内沙箱渲染（见下方规范） |
| **D · HTML 文件** | 用户明确要可分发的文件、或超大型单页应用 | `write_file` 落盘到工作区，告知用户浏览器打开 |

```
用户请求 →
├─ 命中触发白名单？
│   ├─ 否 → 纯 Markdown，禁止为了美化强行画图
│   ├─ 是 → 是地图/地理位置类？→ 禁止地图可视化，回退纯文本/列表/流程图
│         → 需要交互或动态？→ 通道 C（html renderer，聊天内渲染）
│         → 数据图表（趋势/占比/排名/对比）？→ 通道 A（pie/xychart/sankey）+ 通道 B（数据表）
│         → 结构图/流程/关系/时序？→ 通道 A（flowchart/sequence/graph/mindmap/…）
```

## 触发白名单（满足其一才画图）

1. **显式要求**：用户提到可视化、画图、图解、流程图、架构图、趋势图、占比图、关系图、"直观一些"、"用图说明"等。
2. **数据图表显著增益**：趋势、占比、排名、波动、多指标对比（性能数据、市场份额、财务指标、资源用量等）。
3. **教学型动态概念**：参数变化影响曲线/轨迹/分布（函数变换、算法过程、物理过程）。
4. **步骤状态机**：算法逐步执行、状态迁移，用户目标是"看过程"。
5. **结构化知识**：人物/组织关系、因果链路、时间轴、架构分层，用图明显提升理解。

**反触发边界**：
- 代码调试、工程实现、文案改写、普通问答、静态罗列——文字已足够时**禁止**强行输出图。
- **文件产物任务**（生成 PDF/PPT/Word/Excel/图片文件）：必须真实生成文件，不能用图表冒充。
- **地图类绝对禁止**：行政区划、轨迹绘制、坐标标注——离线环境无地图瓦片与地图库，回退纯文本/列表/非地图流程图。

## mermaid 语法要点与陷阱（v11 · securityLevel=strict）

- **节点文本含特殊字符必须加引号**：`A["读取 config.yaml"]`。中文括号 `（）`、冒号、竖线、括号内逗点都会导致解析失败——一律引号包裹。
- **节点 ID 用 ASCII**（`n1`、`svc_db`），不要用中文或 emoji 作 ID；显示名写在方括号里。
- `flowchart` 里 `subgraph` 标题含空格/中文要引号：`subgraph "接入层"`；子图内方向用 `direction LR`。
- 箭头语义：`-->` 实线、`-.->` 虚线（异步/可选）、`==>` 粗线（强调）、`-- "标签" -->` 带说明。
- 分支/循环直接画；并列分支保持同一层级对齐，避免交叉线过多。
- `xychart-beta` 数值轴；`pie` 用 `showData` 在图例带数值。
- **渲染失败时桌面端会显示源码**——发送前自查一遍引号/括号闭合；失败的兜底是紧随其后的数据表格（通道 B）。
- 主题跟随应用明暗：不要在 mermaid 里写死深色背景或浅色文字，用默认主题色。

## 数据真实性（强制）

- 没有可靠数据就**不编数字**。只能输出示例结构，并在图旁明确标注"未取得可靠数据，以下为示例结构"。
- 图表必须配口径说明：数据来源、统计时间、假设条件。时间序列/排名图不得用未声明的示例数据冒充真实数据。
- 用户给了数据 → 原样使用；工具取数（terminal/http 等）→ 以取回结果为准。

## 通道 C：`html type="renderer"` 就地渲染规范

- **围栏格式必须精确**：` ```html type="renderer" `（info string 里的 `renderer` 关键字触发渲染；普通 ` ```html ` 代码块仍按源码显示，用于给用户看 HTML 源码的场合）。
- **运行环境**：沙箱 iframe，`allow-scripts`、无同源、无导航、**零网络**。脚本可自由操作自身 DOM，可 `postMessage` 但父窗口只读取高度。
- **零外部依赖**：禁止引用任何 CDN、外链字体、外链脚本——内网不可达，页面会空白。只用内联 CSS + 原生 SVG/Canvas/JS 手写实现。
- **高度自适应**：桌面端会注入高度上报脚本，内容高度自然撑开、超高内部滚动——**不要写死 `height`/`min-height: 100vh`**，body 不设 `margin: 0` 以外的盒子约束。
- **白色画布**：渲染容器是白底——按浅色主题配色（深色文字 `#1A1B1C`、次级 `#6B7280`），不要假设深色背景。
- 单个代码块 **≤ 300 行**，超出拆成多个 renderer 块（各自独立渲染）。
- 稳定性自检（借鉴 doubao-visualization）：脚本包 IIFE、整体 try-catch、先判 DOM 存在再操作、无死循环；**宁可输出简单但一定能跑的 SVG/Canvas，不要复杂但可能白屏的脚本**。
- 可读性：响应式布局、正文 ≥ 14px、轴标签 ≥ 12px、交互热区 ≥ 44×44px、文本对比度 ≥ 4.5:1。
- 设计取向：内容为王、极简克制。配色从一个低饱和主色出发（如 `#7C9CD0` / `#8BC8EA`），语义色仅用于状态（成功 `#52C41A` / 警告 `#FAAD14` / 错误 `#EA6668`），禁止大面积色块与全局阴影。

## 通道 D：HTML 文件（仅限明确要文件的场景）

用户明确要可分发/可保存的文件，或内容超出单块 renderer 的承载（多视图单页应用）时才走文件通道：`write_file` 落盘到当前工作区（绑定 workspace 的对话里相对路径即可），文件名语义化（如 `deploy-flow.html`），回复中给出路径。规范与通道 C 一致（零 CDN、稳定自检、浅色画布），另需单文件双击可用、不假设本地服务器。

## 输出结构（命中白名单时）

固定交替结构：

1. **简短文字结论**（先说答案，再说图）
2. **可视化本体**（` ```mermaid ` 或 ` ```html type="renderer" ` 代码块，或 HTML 文件路径）
3. **数据表格**（数值类图表必配，给精确值）
4. **解读与口径**：关键峰谷/拐点、最大最小项、数据来源与假设、下一步建议

单图节点 ≤ 15、饼图分片 ≤ 6、表格列 ≤ 8——超过就拆分或聚合"其他"。

## 通道适配（按运行模式，系统提示词已告知当前平台）

上表的 mermaid / html renderer 通道**仅桌面端（serve）真实渲染**。其他模式下降级，禁止输出对方收到只会是文本墙的围栏：

| 模式 | 数据图表 | 结构图/流程 | 交互/动态 |
|------|----------|-------------|-----------|
| 桌面（serve） | mermaid（pie/xychart）+ 表格；**mermaid 表达不了的（横向条形、精确多系列）用 `image_render`**，回复下方自动展示 | mermaid | `html type="renderer"` |
| CLI | GFM 表格（Rich 可渲染表格） | 缩进列表/ASCII 箭头（`A --> B`） | 说明无法交互展示，给静态版本或数据表 |
| 网关（wecom/feishu） | **`image_render(source=data)` 生成 PNG → `send_image(image_path=...)` 投递**；极简场景退化为对齐文本条形（`█████ 45%`） | **`image_render(source=mermaid)` 转图投递**，或编号步骤列表 | 转静态图投递；建议用户到桌面端查看 |

网关消息有长度上限（wecom 4000 字）——可视化数据先行精简聚合，不要贴全量数据。

**转图是无渲染能力通道的补偿手段，不是平级选项**：桌面/CLI 有原生渲染（mermaid / html renderer / Rich 表格），回复一律优先原生形式；`image_render` 仅在通道无渲染能力（网关）、mermaid 表达不了、或用户明确要图片**文件**时使用。桌面下出图后**不要写 `![](...)` 嵌图语法**——桌面会在回复下方自动展示，文字里提路径即可。
